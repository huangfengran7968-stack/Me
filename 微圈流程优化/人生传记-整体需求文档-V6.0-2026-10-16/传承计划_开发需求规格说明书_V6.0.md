# 传承计划｜开发需求规格说明书 V6.0

> 文档类型：产品需求规格 / 研发交付基线  
> 适用团队：产品、UI/UX、客户端、Web 前端、后端、AI、数字人、测试、硬件相框端  
> 需求基线：传承计划 V6.0 正式需求 + V5.4 手机谱系纵向版 HTML  
> 当前终端：手机 APP + 家庭智能相框  
> 文档状态：可进入研发评审 / 技术拆分 / 联调 / QA 验收  
> 优先级定义：P0=本版本必须；P1=重要增强；P2=后续能力  
> 术语中 `必须 / 不得 / 仅` 均为强制需求；`建议 / 推荐` 为技术实现建议，不作为产品强制约束。

---

# 1. 文档目标

本文件将 V6.0 的产品原型描述转换为可直接给研发团队执行的需求规格。

研发交付必须能够明确回答：

1. 页面有哪些；
2. 每个页面从哪里进入、能做什么；
3. 手机 APP 与家庭相框的差异是什么；
4. 数据对象如何关联；
5. 什么字段允许为空；
6. 什么删除操作只解除关系、不能级联删除；
7. 数字生命如何进入、有哪些状态、哪些 UI 禁止出现；
8. 家族谱系手机端与相框端如何使用同一数据但不同方向展示；
9. 后端至少需要提供哪些业务能力；
10. QA 如何判断每一项是否完成。

# 3. 重要边界说明

## 3.1 “无照片”仅指当前 UI Demo 视觉

当前 V6 HTML 原型：

- 不嵌入真实人物照片；
- 不使用家庭合影；
- 不使用时间线照片缩略图；
- 人物使用抽象 CSS / 渐变占位；
- 数字分身使用抽象视觉。

但正式产品数据能力仍必须保留：

- 照片；
- 视频；
- 原声；
- 文字；
- 作品。

因此研发不得因为“Demo 无照片”删除媒体资产模型或上传 / 播放能力。

---

## 3.2 V4.2 为视觉基线

V6.0 不重新设计视觉体系。

必须继续沿用：

- 暖白 / 米色主背景；
- 浅紫 AI / 数字生命强调色；
- 轻描边；
- 低阴影；
- 16—26px 圆角体系；
- 手机端约 16px 页面内边距；
- 约 18px 模块间距；
- 390px 宽度下的紧凑信息密度；
- Hero；
- 时间线；
- `life-row`；
- 数字分身卡；
- 家庭关系画布；
- 相框端双栏重排逻辑。

# 4. 核心业务对象

产品中的核心对象不是页面，而是 `Person`。

同一个 Person 可以同时出现在：

```text
Person
├─ 生命档案
├─ 家庭关系
├─ 家族谱系
├─ 数字分身关联
├─ 年龄阶段
├─ 数字生命
└─ 人生作品
```

所有模块引用同一 `person_id`。

不得因为入口不同创建重复 Person。

---

# 5. 账号模型

## REQ-ACCOUNT-001

一个账号必须存在唯一：

```text
owner_person_id
```

其含义为：

> 当前登录账号本人对应的 Person。

一级导航“生命档案”必须永远打开 `owner_person_id` 对应的生命档案。

---

## REQ-ACCOUNT-002

一个账号对应一套：

```text
Genealogy
```

当前版本不支持一个账号同时管理多套家族谱系。

固定一级模块：

```text
生命档案｜家庭关系｜家族谱系
```

顺序不得修改。

- 留下故事；

作为一级导航。

这些都属于生命档案内部能力。

# 7. 顶部导航规范

## REQ-NAV-001｜手机 APP 顶部单行导航

结构：

```text
‹ [Logo] 传承计划   生命档案   家庭关系   家族谱系
```

一级首页无返回按钮时：

```text
[Logo] 传承计划   生命档案   家庭关系   家族谱系
```

### 强制规则

- 顶部仅一行；
- Logo + 产品名 + 三个一级导航必须同一行；
- 不使用底部一级 Tab；
- 不在导航下面新增“页面标题 / 返回 / 更多”第二行；
- 二级返回按钮直接放 Logo 左侧；
- 当前一级模块高亮。

### 建议尺寸

- Header：54—58px；
- Logo：26—30px；
- 产品名：12—13px；
- 导航文字：10—11px。

---

## REQ-NAV-002｜家庭相框顶部单行导航

结构：

```text
‹ [Logo] 传承计划     生命档案   家庭关系   家族谱系     ✓ 与手机 APP 同步
```

### 强制规则

- 与手机 APP 一级导航名称、顺序完全相同；
- 不使用底部导航；
- 不增加第二层标题栏；
- 可在右侧展示同步状态；
- 返回按钮规则与手机一致。

# 9. 本人生命档案 P-01

## REQ-LIFE-001｜只显示当前账号本人

进入一级“生命档案”时：

```text
person_id = account.owner_person_id
```

不得使用上一次浏览的家庭成员覆盖 owner。

---

## REQ-LIFE-002｜本人生命档案禁止人物切换

P-01 不显示：

- 爸爸；
- 妈妈；
- 儿子；
- 其他家人；
- `＋添加人物`。

---

## REQ-LIFE-003｜页面顺序

手机端固定优先顺序：

```text
Hero
↓
人生时间线
↓
最近留下
↓
数字分身
↓
人生作品
```

可继续向下增加“TA 的记忆 / AI 回顾”等入口，但不得改变时间线的核心位置。

---

## REQ-LIFE-004｜Hero

必须展示：

- `LIFE PROFILE`；
- “我的生命档案”；
- 当前本人姓名；
- 出生年份（有则展示）；
- 已留下故事 / 资料数量摘要；
- 抽象人物视觉；
- `查看人生时间线`；
- `＋留下一段人生`（手机 APP）。

相框端不显示生产类按钮。

---

## REQ-LIFE-005｜0 资料状态

Person 已存在但 LifeNode 为空时：

必须允许页面正常展示。

必须展示：

```text
还没有生命记录
```

以及手机端完善入口。

不得因为：

- 0 照片；
- 0 声音；
- 0 故事；
- 0 数字分身；

阻断 Person 存在或页面打开。

# 11. 家庭关系 P-13

## REQ-FAM-001｜页面职责

只解决：

> 当前家庭有哪些人、与本人是什么关系。

不得承担多代族谱展示。

---

## REQ-FAM-002｜家庭关系画布

至少支持：

- 父亲；
- 母亲；
- 本人；
- 配偶；
- 子女；
- 兄弟姐妹。

人物采用轻量抽象节点。

关系线为简洁连接线。

---

## REQ-FAM-003｜人物点击

点击家庭人物：

```text
person_id
→ P-15 他人生命档案
```

本人节点点击：

```text
→ P-01 本人生命档案
```

---

## REQ-FAM-004｜添加家庭成员

手机 APP 最低必填：

| 字段 | 必填 | 说明 |
|---|---:|---|
| 姓名 | 是 | 可使用称谓前先建人物 |
| 与我的关系 | 是 | 父亲/母亲/配偶/子女/兄弟姐妹等 |

以下允许为空：

- 出生年份；
- 离世年份；
- 籍贯；
- 头像；
- 故事；
- 声音；
- 数字分身；
- 谱系信息。

---

## REQ-FAM-005｜保存后不得自动加入谱系

保存家庭成员后：

```text
FamilyRelation 创建成功
```

不得自动创建 GenealogyNode 或 GenealogyNodePersonLink。

前端提示：

```text
已添加到家庭关系。
是否前往家族谱系继续关联？

[稍后]
[前往家族谱系]
```

---

## REQ-FAM-006｜从家庭关系移除

删除家庭关系：

只删除 / 失效 FamilyRelation。

不得删除：

- Person；
- LifeProfile；
- LifeNode；
- DigitalAvatar；
- DigitalLife；
- GenealogyNodePersonLink。

# 12. 家族谱系 P-16

## REQ-GENE-001｜同一账号唯一谱系

```text
Account 1 : 1 Genealogy
```

---

## REQ-GENE-002｜终端方向

同一份 `GenealogyNode[]`：

### 手机 APP

```text
上
↓
节点1
│
节点2
│
节点3
│
＋
↓
下
```

### 家庭相框

```text
节点1 ─ 节点2 ─ 节点3 ─→
```

方向仅为 UI 适配，不得生成两份数据。

---

## REQ-GENE-003｜手机端必须纵向

手机端：

- 主轴纵向；
- 节点自上而下；
- 通过上下滚动浏览；
- 不以横向拖动作为主要谱系浏览交互；
- 当前最后节点下方显示 `＋`；
- 新节点成功后自动向下延展；
- 保存成功后应滚动 / 定位到新增节点或新的末尾 `＋`。

---

## REQ-GENE-004｜相框端必须横向

相框：

- 主轴横向；
- 从左往右；
- 节点顺序必须与手机一致；
- 可横向滚动 / 平移；
- 只读；
- 不提供真实创建 `＋` 操作。

---

## REQ-GENE-005｜空状态

### 手机

必须保留纵向主轴语义并显示：

```text
＋ 创建起始节点
│
↓
```

### 相框

无节点时允许展示：

```text
尚未建立家族谱系
```

如保留 `＋` 视觉，只能是只读提示，点击后不得直接创建。

# 13. GenealogyNode P-17/P-18

## REQ-GNODE-001｜节点语义

GenealogyNode 表示：

- 世次；
- 时期；
- 家族发展阶段；
- 待确认溯源阶段。

不得默认等同一个 Person。

---

## REQ-GNODE-002｜创建最低要求

最低只要求：

```text
title
```

例如：

```text
第一代
```

其余字段全部允许为空。

---

## REQ-GNODE-003｜节点字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| id | UUID/string | 系统 | 唯一 ID |
| genealogy_id | UUID/string | 是 | 所属谱系 |
| title | string | 是 | 第一代 / 家族起点 / 自定义 |
| generation | string | 否 | 第一代、第二代等 |
| period | string | 否 | 约1930—1960 |
| summary | text | 否 | 节点说明 |
| source | text/json | 否 | 资料来源 |
| sequence_index | int | 是 | 技术排序字段 |
| created_at | datetime | 系统 | 创建时间 |
| updated_at | datetime | 系统 | 更新时间 |

> `sequence_index` 为研发落地补充字段，用于保证手机纵向顺序与相框横向顺序完全一致。

---

## REQ-GNODE-004｜创建顺序

新节点默认：

```text
sequence_index = 当前最大值 + 1
```

本版本 P0 不要求任意拖拽重排。

---

## REQ-GNODE-005｜节点详情

节点详情必须返回：

- title；
- generation；
- period；
- summary；
- source；
- 对应人物列表；
- 谱系记录（如有）。

---

# 14. 谱系节点人物管理 P-19

## REQ-GPERSON-001

一个 GenealogyNode：

```text
0...N Person
```

一个 Person 允许出现在：

```text
1...N GenealogyNode
```

若后端最终业务决定限制 Person 只能属于一个主世次，需要另开产品评审；V6.0 当前不做此限制。

---

## REQ-GPERSON-002｜人物来源

支持：

1. 关联家庭关系已有 Person；
2. 关联账号内已有 Person；
3. 创建新 Person；
4. 导入识别后用户确认创建。

---

## REQ-GPERSON-003｜创建新谱系人物最低要求

谱系中的新 Person 允许极简。

最低：

```text
name 或 relation_label 至少有一项可展示
```

产品示例允许：

```text
父亲
信息待完善
```

> 后端实现建议：Person `name` 可暂存“父亲”等显示名；如技术不允许 name 为空，则 UI 中的关系称谓可作为临时 name。正式实名可后续修改。

---

## REQ-GPERSON-004｜解除节点人物关联

只删除：

```text
GenealogyNodePersonLink
```

不得删除 Person 和生命档案。

# 15. Person 数据规格

## 15.1 必要字段

```text
Person
├─ id
├─ account_id
├─ name
├─ birth_year?
├─ death_year?
├─ summary?
├─ created_at
└─ updated_at
```

## 15.2 关系字段不得直接写死在 Person

“爸爸 / 妈妈 / 儿子”本质是人与 owner 的关系。

```text

```

不要把唯一 `relation` 字段作为 Person 的永久身份。

原因：

同一个 Person 对不同人关系不同。

## REQ-DL-005｜实时状态机

```text

↓

↓

↓

↓
```

## REQ-DL-006｜状态文案

| 状态 | UI |
|---|---|
| IDLE | 想和我聊些什么？ |
| LISTENING | ● 正在听你说 |
| UNDERSTANDING | 正在回想…… |
| SPEAKING | ● {人物称谓}正在回答 |
| ERROR | 暂时没听清，可以再说一次 |

---

## REQ-DL-007｜实时链路

生产目标链路：

```text

→ ASR
→ Query
→ 按 person_id + stage_id 检索
→ 应用 memory_cutoff_age
→ 生成回答
→ TTS 使用人物声音
→ 数字人口型 / 表情同步
→ 播放
```

---

## REQ-DL-008｜记忆边界

检索条件必须包含：

```text
LifeNode.age <= LifeStage.memory_cutoff_age
```

或等价年份逻辑。

禁止模型读取阶段之后的人生事实再“假装不知道”。

应在检索层直接隔离。

---

## REQ-DL-009｜无资料

当检索不到已确认资料：

回答语义必须等价：

```text
这件事现在还没有被记录下来，我还想不起来。
```

不得编造。

---

## REQ-DL-010｜超年龄

用户询问阶段之后的事件：

回答语义必须等价：

```text
那是我这个年龄之后的事情，现在的我还没有经历呢。
```

---

## REQ-DL-011｜字幕

字幕只显示：

1. 当前用户一句实时识别；
2. 当前数字生命正在说的一句。

不得累积为消息列表。

退出页面后不要求以聊天记录形式保存。

- WebSocket；
- SSE；



# 36. 非功能要求

## NFR-001｜数据一致性

Person 为主实体。

跨模块引用必须使用 ID，不使用姓名做唯一匹配。

---

## NFR-002｜幂等

以下操作需避免重复：

- 添加同一 FamilyRelation；
- 同一 GenealogyNode 关联同一 Person；
- 重复点击创建 LifeStage；
- 同一 Avatar 重复绑定同一 Person。

后端应支持幂等或冲突返回。

---

## NFR-003｜时间线性能

P0 人物 100 个 LifeNode 内：

手机端首次渲染不应明显卡顿。

具体性能数字由技术结合框架设定。

---

## NFR-004｜相框离线

相框离线不影响 APP 保存。

云端保存成功即视为用户数据保存成功。

---

## NFR-005｜AI 不编造事实

AI 人生采访整理、AI 回顾、数字生命均必须基于已确认资料。

对于无法确认的事实：

- 返回无资料；
- 不自动补全。

# 38. QA 主验收路径

## Case A｜本人生命档案

1. 登录；
2. 点击生命档案；
3. 验证 person = owner；
4. 验证无人物切换；
5. 查看时间线；
6. 点击年龄阶段；
7. 进入数字生命；
8. 点击麦克风；
9. 验证状态按 LISTENING → UNDERSTANDING → SPEAKING；
10. 验证无聊天输入框。

---

## Case B｜家庭人物

1. 点击家庭关系；
2. 点击爸爸；
3. 进入爸爸生命档案；
4. 验证顶部一级高亮仍是家庭关系；
5. 验证出现家庭人物切换；
6. 切换妈妈；
7. 验证 owner 未变化；
8. 点击一级生命档案；
9. 验证立即回到本人。

---

## Case C｜家庭人物新增

1. 家庭关系点击添加；
2. 只填写姓名 + 关系；
3. 保存；
4. 验证 FamilyRelation 成功；
5. 验证家族谱系未自动新增节点；
6. 验证 Person 可打开空生命档案。

---

## Case D｜手机家族谱系

1. 谱系无节点；
2. 验证出现纵向主轴 + 一个 `＋`；
3. 创建“第一代”；
4. 验证节点从上往下展示；
5. 验证新的 `＋` 位于下方；
6. 继续创建第二代；
7. 验证顺序正确；
8. 关联爸爸；
9. 点击爸爸进入生命档案。

---

## Case E｜相框家族谱系

1. 手机创建第一代、第二代、第三代；
2. 切换 / 打开相框；
3. 验证同一节点按横向显示；
4. 验证顺序与手机一致；
5. 验证不可创建；
6. 点击第二代；
7. 查看人物；
8. 进入人物生命档案。

---

## Case F｜删除关系不删数据

1. 创建爸爸 Person；
2. 建立家庭关系；
3. 建立生命节点；
4. 将爸爸关联谱系节点；
5. 从家庭关系移除爸爸；
6. 验证 Person 仍存在；
7. 验证生命档案仍存在；
8. 验证谱系关联仍存在。

---

## Case G｜数字生命记忆边界

1. 妈妈存在 20岁、27岁、36岁、61岁 LifeNode；
2. 创建 36岁 LifeStage；
3. 进入 36岁 DigitalLife；
4. 查询 61岁事件；
5. 后端检索不得返回 61岁节点；
6. 数字生命回答“这个年龄还没有经历”语义；
7. 不得引用未来事件。

# 39. 发布阻断项

以下任一出现，本版本不得验收通过：

- 一级生命档案还能切爸爸 / 妈妈；
- 一级生命档案出现添加人物；
- 顶部导航下面还有独立第二行标题栏；
- 手机仍有底部一级导航；
- 手机家族谱系仍横向为主；
- 相框家族谱系仍纵向；
- 手机 / 相框各保存一套独立谱系数据；
- 谱系节点被实现成“一个节点=一个 Person”；
- 删除 FamilyRelation 导致 Person 被删除；
- 数字生命存在文字输入框；
- 数字生命存在发送按钮；
- 数字生命存在聊天历史；
- 数字生命可以检索年龄阶段之后的 LifeNode；
- AI 人生回顾无法回溯 LifeNode 来源；
- 相框出现人物 / 谱系新增编辑能力；
- 因 Demo 无照片而删除正式产品媒体资产能力。

```text
同一个 Account

一级生命档案只属于 owner

└─ 相框：横向

Person
↓
LifeNode + LifeStage + DigitalAvatar

DigitalLife

实时语音数字人

家庭相框
```
